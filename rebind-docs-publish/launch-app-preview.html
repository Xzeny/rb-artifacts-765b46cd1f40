Launch an App from a Key

Start an app with a key press on Windows and macOS, or focus it when it is already running, with rb.system.exec_detached and rb.app as complete Luau scripts.

Each recipe is a complete script. Paste it into a new script in the Rebind app, start it, and adjust its settings in the script's Options tab. Starting a program needs the exec permission.

rb.app.activate brings forward an app that is already running and never launches one. To start an app, use rb.system.exec_detached: it starts the program directly, without a shell, returns its process id at once, and leaves the program running after the script stops.

Launch an app on Windows

Pass the full path to the .exe. Arguments go in args, one string each, passed as given. There is no shell, so a path with spaces needs no quotes and %VARIABLES% are not expanded; read them with rb.env.get.

--[[
  rebind: min_sdk=3.9.0
  rebind: name=Launch App (Windows)
  rebind: version=1.0.0
  rebind: platforms=windows
  rebind: permissions=exec
  rebind: permission_reason="exec: Starts the app you choose"
]]
local cfg = rb.ui.schema({
  key = rb.ui.keybind("F8", { label = "Launch key" }),
  exe = rb.ui.text([[C:\Windows\System32\notepad.exe]], { label = "Program (.exe path)", max_length = 260 }),
})

rb.bind(cfg.key, rb.async(function()
  local ok, err = pcall(function()
    rb.system.exec_detached(cfg.exe)
  end)
  if not ok then
    rb.log.error(err)
  end
end))

To pass arguments or start in a folder, add options. A per-user install under %LOCALAPPDATA% reads the folder from the environment:

local exe = rb.env.get("LOCALAPPDATA") .. [[\Programs\Microsoft VS Code\Code.exe]]
rb.system.exec_detached(exe, { args = { [[C:\work\my project]] }, cwd = [[C:\work]] })

Launch an app on macOS

Start apps with macOS's open command. -a takes the app's name as it appears in /Applications; a full .app path also works in its place.

--[[
  rebind: min_sdk=3.9.0
  rebind: name=Launch App (macOS)
  rebind: version=1.0.0
  rebind: platforms=macos
  rebind: permissions=exec
  rebind: permission_reason="exec: Starts the app you choose"
]]
local cfg = rb.ui.schema({
  key = rb.ui.keybind("F8", { label = "Launch key" }),
  app = rb.ui.text("TextEdit", { label = "App name", max_length = 100 }),
})

rb.bind(cfg.key, rb.async(function()
  local ok, err = pcall(function()
    rb.system.exec_detached("/usr/bin/open", { args = { "-a", cfg.app } })
  end)
  if not ok then
    rb.log.error(err)
  end
end))
Note

exec_detached returns the id of the program passed as cmd. Here that is the open command, not the app it opens. To check on the app itself, use rb.app.is_running.

Launch or focus

One key focuses the app when it is running and starts it when it is not. rb.app.is_running and rb.app.activate name apps by executable on Windows (.exe optional) and by display name on macOS, ignoring case. The script branches on rb.info.platform, so the same file runs on both.

--[[
  rebind: min_sdk=3.9.0
  rebind: name=Launch or Focus
  rebind: version=1.0.0
  rebind: permissions=exec
  rebind: permission_reason="exec: Starts the app when it is not running"
]]
local APPS = {
  windows = {
    name = "notepad",
    start = function()
      rb.system.exec_detached([[C:\Windows\System32\notepad.exe]])
    end,
  },
  macos = {
    name = "TextEdit",
    start = function()
      rb.system.exec_detached("/usr/bin/open", { args = { "-a", "TextEdit" } })
    end,
  },
}

local app = APPS[rb.info.platform]

rb.bind("F8", rb.async(function()
  if rb.app.is_running(app.name) then
    -- activate raises when no window matches, for example a tray-only app
    if pcall(rb.app.activate, app.name) then
      return
    end
  end
  local ok, err = pcall(app.start)
  if not ok then
    rb.log.error(err)
  end
end))

rb.app.activate raises when nothing matches, so it runs inside pcall, and the script falls back to starting the app. On macOS, activate on a hidden app first shows it, and a second press brings it forward.

Things to know

  • activate never launches. It raises when no running app matches. Start apps with exec_detached.
  • No shell. Pipes, &&, %VAR% and ~ do nothing; build the path in Luau and pass the full path to the program. For a shell command, use rb.system.exec, which runs through cmd.exe /C on Windows and sh -c on macOS and waits for the command, so call it inside rb.run.
  • Errors. A program that cannot start raises exec detached spawn failed: <reason>. The scripts catch it with pcall and write it to the script's Logs.
  • No output. exec_detached discards the program's output. To read a command's output, use rb.system.exec.
  • Permission. Without exec, the call raises System.Exec() requires 'exec' permission and Rebind stops the script, even inside pcall. A marketplace package must give a reason for exec.
  • Tray apps on Windows. activate focuses a visible window, so an app running only in the tray makes it raise, and the launch-or-focus script starts the app instead.

Requirements

  • Windows 10 or 11, 64-bit, or macOS 13 or later on Apple Silicon. See Platforms.
  • The exec permission.
  • On macOS, rb.app.activate needs Accessibility for Rebind Relay, the same permission software mode needs.
