11.1 Recommendation

  • Option: (b) Vercel domain redirect. Add rebind.app and www.rebind.app to the Vercel project that serves www.rebind.gg, set each to "Redirect to www.rebind.gg", and point rebind.app's GoDaddy DNS at Vercel.
  • Status code: 301 (Moved Permanently). Google treats both 301 and 308 as permanent and passes signals through either. 301 is the most widely understood code across SEO tools, crawlers and AI fetchers. 308's advantage is that it preserves the request method and body (POST stays POST), which only matters for APIs or forms, and rebind.app has neither. Vercel's domain-redirect setting lets you pick 301 or 308. If the team prefers Vercel's 308 default, that's equally acceptable for SEO.
  • Paths: preserve path and query (rebind.app/foo?x=1 → https://www.rebind.gg/foo?x=1). Vercel domain redirects do this automatically. It's one hop with no chain: a path that exists on www.rebind.gg (for example /compare/autohotkey) lands correctly, and an unknown path ends in a single 404 on www.rebind.gg. rebind.app never had content (parked since Sep 2024), so no old deep links need mapping. Sending everything to the homepage would only add value if paths caused 404 chains, and they don't here. If option (a) is used instead and GoDaddy drops the path, everything lands on the homepage, which is also acceptable for a domain that never had pages.
  • Why not the alternatives: (a) GoDaddy forwarding is the simplest no-Vercel fallback, but GoDaddy doesn't document path/query handling and only offers 301/302. (c) Cloudflare isn't in use anywhere in this setup (rebind.app DNS is GoDaddy; rebind.gg DNS is AWS Route 53; www.rebind.gg is served by Vercel). Adding it would mean a nameserver move for no gain.

11.7 Verification checklist (after the change)

Run from a normal network (my box's plain-http egress returns proxy 500s):

for h in rebind.app www.rebind.app; do
  for s in https http; do
    for p in "/" "/compare/autohotkey" "/foo?x=1"; do
      echo "== $s://$h$p"; curl -sI "$s://$h$p" | grep -iE '^HTTP|^location'
    done
  done
done
# full chain, should be ONE hop to www.rebind.gg:
curl -sIL https://rebind.app/compare/autohotkey | grep -iE '^HTTP|^location'
# certificate:
echo | openssl s_client -connect rebind.app:443 -servername rebind.app 2>/dev/null | grep -E 'subject=|Verify return'
echo | openssl s_client -connect www.rebind.app:443 -servername www.rebind.app 2>/dev/null | grep -E 'subject=|Verify return'

Pass criteria: - [ ] https://rebind.app/ and https://www.rebind.app/ → one 301 with location: https://www.rebind.gg/, then 200. - [ ] Deep path and query: https://rebind.app/foo?x=1 → location: https://www.rebind.gg/foo?x=1 (Vercel). With GoDaddy forwarding, record whether the path is dropped; homepage is acceptable. - [ ] /compare/autohotkey ends at https://www.rebind.gg/compare/autohotkey with 200. - [ ] No hop through https://rebind.gg (no 307 anywhere in the -L chain). - [ ] Valid certificate for both rebind.app and www.rebind.app (verify return code 0); no browser warning. - [ ] http:// versions reach the same target (one or two hops; http matters little since .app is HSTS-preloaded). - [ ] No masking or iframe: response is a 3xx with a location header, not a 200 page containing a <frame>/<iframe>, and the browser address bar shows www.rebind.gg. - [ ] Browser check (Chrome and Safari, private window): typing rebind.app lands on www.rebind.gg. - [ ] Optional, Google Search Console: add a Domain property for rebind.app (DNS TXT verification) to watch crawl and redirect status. Change of Address is probably not applicable: it's for moving an existing site with indexed content, and rebind.app has only ever been a parked page. A plain redirect is enough. - [ ] AI Search Visibility keeps re-checking ChatGPT daily ("AutoHotkey alternatives" → the "Rebind website" link). Even if ChatGPT keeps citing rebind.app for a while, users will land on www.rebind.gg.

11.9 Rollback

  • Option (b): in Vercel, remove rebind.app and www.rebind.app from the project (or clear the redirect). In GoDaddy DNS, restore the saved records (@ A 3.33.130.190 and 15.197.148.33 for parking, www CNAME @), or re-enable parking.
  • Option (a): GoDaddy → DNS → Forwarding → Delete the rule. That unlocks the @ A record, which can then be restored as above.
  • Caveat: browsers cache 301s, so repeat visitors may keep being sent to www.rebind.gg after a rollback. That's harmless here (the target is our own site), and it's another reason not to use 301 for anything we might point elsewhere later.
