1. Bottom line for the CEO

  1. Activation is the named script doing its visible job. A completed install, first launch or welcome tour doesn't count. Someone has activated only when all three happen: they install Rebind, then separately install the named Marketplace script, then see the script do the thing they came for. [Verified-source: B, G]
  2. The biggest structural risk is the gap between the two installs. Installing Rebind does not install any script [Verified-source: B, G]. Someone who arrived for "the keystroke overlay" can finish the app install with no overlay and no clear next step. Every discovery space should hand off a named job plus the exact listing, not a generic "download Rebind." [Inference]
  3. Permission and OS screens are the second big risk. These include Windows Administrator PowerShell, macOS Accessibility, the script's own permission screen, and capture permissions such as OBS Display Capture or macOS Screen Recording/Capture. We should explain each one before it appears and allow a clean "no." We should never tell anyone to click past a security warning. [Verified-source: P, G; Inference: handling]
  4. We can't see past the download click today. passRefToInstaller=false, so ?ref= stops at download-start. Install, script install and activation can't be tied to a space. Even the web events still need their collection verified. [Verified-source: G, L, H]
  5. Help should live in the page and the app before any email. Local scripts need no account, so the free path needs no email address. Lifecycle support should be on-page and in-app first. Email and SMS stay out of scope until there's consent, a verified trigger and Dean's specific approval. [Verified-source: P; Inference: priority]

3. Journey map: discovery → install → marketplace script → first useful result

Worked example: Keystroke Overlay (@rebind/keystroke-overlay, listing https://www.rebind.gg/marketplace/script_FhIdJaL7uLVeBUjo6gcuQ). It's the strategy-brand beachhead job and appears in the dossier as named marketplace proof, with freshness limits. [Verified-source: P, S] The same shape applies to any named script.

StepWhat the person is askingTruth that has to be visible hereWhat they should see (UNPUBLISHED concept)
1. Discovery space"Can I get that overlay?"One job, an honest demo, limits shown first. Any later human post starts "Disclosure: I work on Rebind." [Verified-source: B, S]n/a: no space activity is proposed here
2. Job page / guide"Will it work on my computer?"Windows 10/11 64-bit or macOS 13+ Apple Silicon only, with no Linux and no Intel Mac. The app is free, and local scripts need no account or hardware. The listing name and URL stay visible; a "copy both links" button covers people browsing on a phone.
3. App install"Can I trust this, and what will it ask?"Windows source instructions use Administrator PowerShell. The macOS flow needs Accessibility permission. [Verified-source: P]Permission preview: what each prompt is, why it's asked, and what to do on a managed or work machine (ask IT, don't bypass).
4. First launch"Now what?"Installing Rebind does not install the script [Verified-source: B, G]. No deep link or intent recovery is confirmed [Unknown: G]."You're halfway" note on the job page: return to the listing link and open it in Rebind/Marketplace.
5. Script install"What does this script access, and does it cost anything?"Third-party scripts run only within permissions the user approves. Marketplace purchases can be one-time or subscription. Whether a Marketplace install needs an account is not confirmed. [Verified-source: P, G; Unknown: account, price for this listing]Permission explainer from verified listing metadata only. If the listing has a price or account condition, it's stated here, before the person invests time.
6. First action"What do I try?"Overlay: Rebind 3.14.0+, Display Capture (OBS) or macOS Screen Capture/Recording; app-window capture misses it; hidden in Windows exclusive fullscreen; set "Show in screenshots and recordings." [Verified-source: G, S]First-run checklist: set the capture source → press a key → record a 5-second clip. Kill switch shown alongside: Left Ctrl+Left Alt+K (Mac: Left Control+Left Option+K) [Verified-source: P].
7. Confirm result"Did it actually work?"Activation means the overlay is visible in the recorded clip, not just showing as enabled in the UI. [Verified-source: G; Inference]"Not showing?" decision tree: capture mode → system permission → fullscreen mode → version → stop with an honest "not supported in this setup."
8. Repeat use"Do I want this next time?"No forced watermark, share prompt or upsell [Verified-source: G]Optional, user-invoked setup notes. No outbound follow-up based on click history.

5. The no-account, no-email path (must always work)

[Verified-source: P] Local scripts need no account and no hardware. So the full S0→S5 path has to be completable by someone who never gives us an email address. [Inference] Consequences:

  • No email gate on the job page, the download, or the first-run checklist.
  • Help reaches people through owned pages and (later, if product approves) in-app surfaces, not outbound sends.
  • Phone-to-desktop handoff uses a user-initiated copy/save of both links. No "email me the link" field unless separately approved with consent.
  • Being a local user is not consent to be marketed to.
